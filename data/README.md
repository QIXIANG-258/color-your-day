# data —— 颜色库源数据

这里是「Color Your Day」的**源数据**。页面实际读取的是由这些文件编译出来的
`assets/js/colors_data.js`，**不要直接改那个文件** —— 下次编译会被覆盖。

目标：攒满 365 个。**已经满了 —— 365 个，一年 365 天一天一个不重样。**

> 集满之后再加颜色，轮换周期就会超过一年（第 366 天回到第一个，之后每年错开一位）。
> 那没问题，只是「一年不重样」成立的前提是**库 ≥ 365**，别掉到 365 以下。
>
> 另有一条硬约束：**库 ≥ 64**。方阵每格是「整轮洗牌抽出来的」，
> 库不足 64 必有格子重复，还可能挨在一起。所以加颜色不只是攒数，
> 它直接决定首页那块方阵好不好看。

## 四个分类文件

按来源分四类，一个文件一类。**编译时的顺序 = 每日轮换的顺序**：
先轮完西方颜料，再轮中国传统色，然后品牌色、故事色，然后回到第一个。

| 文件 | 类别 | 条数 | 收什么 |
|---|---|---|---|
| `western_pigments.json` | 西方历史颜料 | 85 | 群青、泰尔紫、埃及蓝、木乃伊棕这类有来头的颜料 |
| `chinese_traditional.json` | 中国传统色 | 125 | 天青、月白、胭脂这类传统色名（含诗词来源的） |
| `brand_named.json` | 品牌与命名色 | 75 | 蒂芙尼蓝、爱马仕橙这类被某家占住（或艺术家命名）的颜色 |
| `story_colors.json` | 有故事的色 | 80 | 最粉的粉、最丑的颜色、最黑的黑这类，重点在故事 |

## 一条颜色长什么样

```json
{
  "id": "klein-blue",
  "zh": "克莱因蓝",
  "en": "International Klein Blue",
  "hex": "#002FA7",
  "swZh": "IKB · 1960",
  "swEn": "IKB · 1960",
  "aliasZh": "国际克莱因蓝 · IKB",
  "aliasEn": "International Klein Blue · IKB",
  "histZh": "……历史，一段话",
  "histEn": "……",
  "funZh": "……趣闻，一段话",
  "funEn": "……"
}
```

| 字段 | 必填 | 干什么用 |
|---|---|---|
| `id` | ✅ | 唯一标识，小写英文短横线。用来去重 |
| `zh` / `en` | ✅ | 弹窗里的大标题，按当前语言显示 |
| `hex` | ✅ | 色号，`#RRGGBB`。**方阵的明暗、RGB 三个数都从它算出来** |
| `swZh` / `swEn` | | 压在色块里的那行小字（别名、年份这类短标签，别超 14 字） |
| `aliasZh` / `aliasEn` | | 标题下面那行补充说明 |
| `histZh` / `histEn` | | 「历史」那一段 |
| `funZh` / `funEn` | | 「趣闻」那一段 |

除 `id / zh / en / hex` 外全都可以不写，缺了弹窗里就少一块，不会报错。
分类名（「中国传统色」这类）由文件顶部的 `catZh / catEn` 统一给，不用每条写。

## 加一个新颜色

1. 打开对应的分类文件，在 `items` 数组里加一项
   （**加在哪个位置，就排在轮换顺序的哪个位置**）；
2. 跑一次编译：

   ```bash
   python tools/build_colors.py          # 体检 + 编译，体检不过会拒绝写盘
   python tools/build_colors.py --check  # 只核对产物与源是否一致
   ```

编译器会拦的：hex 格式、id 重复、中文名重复（跨分类也算）、
**字段名拼错**（多出来的键直接点名报错）。
只警告不拦的：两条颜色共用同一个 hex（故意撞色是合理的，
比如「蒂芙尼蓝」和嘲讽它的那个蓝）。

## 正文的量

每条颜色的 `histEn` 建议 ≥ 300 字符（英文天然比中文长）、`histZh` ≥ 85、
`funZh` ≥ 70——弹窗右栏才不显得空。只有一两条新加的偷懒，弹窗就一边满一边空。

## 色相分布

攒颜色时建议按色相角分 12 桶复查一遍分布：某一档堆太多，方阵抽出来就偏色。
（本库 365 条的分布：红+橙+玫红约四成，是刻意保留的暖色调倾向。）
